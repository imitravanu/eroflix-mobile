# P01 foundation commands and ownership

Run Android commands from `mobile/`. The Linux Gradle launcher selects the P00
project-local JDK/SDK before launching Java. Standard Gradle wrapper JAR, Windows
script and checksum-pinned distribution are generated by Gradle 9.6.0. The small
Linux environment block in gradlew is the documented customization; regenerating
the wrapper must preserve it before Java command selection.

```sh
./gradlew --version
tools/dev/verify-foundation.sh
# Equivalent host checks:
./gradlew assembleDebug lintDebug verifyUnitTests :app:assembleDebugAndroidTest
```

The host script is suitable for CI after `python3 tools/dev/setup.py`. It uses
neutral fixture assets and compiles device tests without launching a phone.
Gradle is limited to a 1536 MiB heap and two workers with project parallelism
disabled; the Kotlin compiler runs in-process. Do not start simultaneous builds.

## Connected tests

Connect, unlock and authorize the API 37 Pixel 6 or an explicitly recorded API 37 emulator.
Select its local serial with `ANDROID_SERIAL`, then run:

```sh
./gradlew verifyAndroidTests
```

`require-device.py` checks selection, authorization and API before the real
`:app:connectedDebugAndroidTest` task may install any instrumentation APK. A
missing/disconnected/mismatched device is an error, never a passing device test.
Do not save serials or raw device logs in tracked files. Remove any debug fixture
`adb reverse` mappings after their owning tests.

The smoke suite covers launch/navigation, query restoration across tabs,
rotation/recreation, API/package/window settings, contained debug cleartext
policy, and native SQLite loading/FTS5. Pixel codec and biometric results are
available under Settings → Device diagnostics and must be measured on that phone.

## Platform boundaries

- app owns its manifest, FileProvider, navigation, container and shared settings
  DataStore (`eroflix_settings`). Feature owners contribute through integration.
- P05 adds the playback session/service and playback foreground-service type;
  P06 adds durable download service/scheduling; P07 adds export service. No empty
  services, foreground permissions or notification prompts are introduced early.
- Notification channels are stable `playback`, `downloads`, `exports`; text must
  be redacted under the P08 lock policy before real media work uses them.
- FileProvider authority is `${applicationId}.files`, exported=false, with only
  app-cache `exports/` exposed. SAF user-owned destinations remain a P07 concern.
- Main network policy allows system-trusted HTTPS only. Debug overrides allow
  cleartext solely to localhost/127.0.0.1 for explicit loopback fixtures; production
  has no LAN dependency. Actual LAN tests require API 37 permission handling.
- core:data packages AndroidX bundled SQLite through standard AAR dependencies;
  P02 owns schemas/read leases/migrations. core:network owns the shared HTTP
  client factory, with redirects awaiting P03 destination/header validation.
- core:media packages Media3; P05/P06 create one player/session/cache owner.
  Composables do not construct players. Feature modules grow in their phases.

## Native 16 KiB acceptance

Inspect the built APK with `zipalign -c -P 16 -v 4`, inspect all packaged ELF
PT_LOAD alignments (at least 0x4000), and record native ABIs. A supplemental
16 KiB API 37 runtime must then execute the SQLite smoke test. The user's Pixel
6 baseline is 4 KiB and cannot substitute for that supplemental runtime test.
P10 retains the runtime gate even if static APK/ELF inspection passes.

## Release boundary

This phase creates a debug preview. Release assembly fails until P02 introduces
verified full-catalog asset provisioning and a production container. Debug
fixtures are never an implicit production fallback. P11 owns release signing.

## Device result

The four instrumented tests passed on the unlocked Pixel 6 / API 37. Keep the
phone unlocked during rotation tests; a locked phone can prevent configuration
changes even when semantic UI interactions succeed. Espresso 3.7.0 is explicitly
pinned because the older Compose transitive 3.5.0 build cannot initialize its
input injector on API 37. See [device validation](reports/P01_DEVICE_VALIDATION.md).
